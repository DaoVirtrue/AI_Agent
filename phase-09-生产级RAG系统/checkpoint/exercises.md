# Phase 09 检测练习 (Checkpoint Exercises)

本检测覆盖Phase 09全部13个模块，共10道练习。每道题后标注了对应模块编号。

---

## 练习1: 数据管道完整性验证 (模块01)

**场景**: 你继承了一个不完整的数据管道，只实现了PDF解析和简单分块。

**任务**:
1. 补充缺失的管道阶段: Web解析、去重、元数据增强、BM25索引
2. 实现进度回调机制，在每个阶段完成后输出进度百分比
3. 添加错误处理：单个文档解析失败不应中断整个管道
4. 编写5条质量门控检查规则

**验收标准**:
- 管道支持至少3种文档格式
- 重复文档被正确移除（MD5+语义双重检查）
- 单个文档错误不应导致管道崩溃
- 质量门控报告包含通过/失败状态

## 练习2: 多租户安全隔离 (模块02)

**场景**: 公司产品需要从单租户升级为多租户SaaS平台。

**任务**:
1. 设计FREE/PRO/ENTERPRISE三级配额方案（文档数、chunk数、API调用数、速率限制）
2. 实现三层隔离：集合级 + 元数据级 + API Key认证
3. 编写穿透测试脚本，验证以下安全场景：
   - 伪造API Key
   - 空tenant_id过滤
   - 缓存跨租户污染
4. 实现租户注销流程（软删除、密钥撤销、数据保留策略）

**验收标准**:
- 不同等级租户有不同配额限制
- API Key失效后无法访问数据
- 穿透测试脚本发现至少3种潜在漏洞
- 注销后数据不可访问但可恢复（30天内）

## 练习3: 缓存命中率优化 (模块03)

**场景**: 当前系统只有L1（精确查询缓存），命中率仅3%。

**任务**:
1. 实现完整的四级缓存系统（L1-L4）
2. 编写缓存命中率模拟器，模拟10000次真实查询分布（幂律分布）
3. 计算加入L2/L3/L4后的预期命中率提升
4. 实现索引更新时L3缓存自动失效的事件驱动机制
5. 编写缓存预热脚本，预加载top-100高频查询

**验收标准**:
- 四级缓存全部实现并可通过配置开关
- 缓存统计包含每级命中率、平均延迟
- 索引更新后L3缓存自动清空
- 预热脚本在30秒内完成100条数据加载

## 练习4: 熔断器配置调优 (模块05)

**场景**: 你的熔断器配置过于激进，频繁因LLM API 429错误进入OPEN状态。

**任务**:
1. 分析当前配置问题: `failure_threshold=3, failure_window=30s, timeout=60s`
2. 设计LLM API / Vector DB / Reranker三个依赖的正确配置
3. 实现错误分类函数，将429/速率限制错误排除在熔断计数外
4. 实现指数退避：每次重新进入OPEN，冷却时间翻倍（最大5分钟）
5. 编写熔断器单元测试：模拟正常请求、连续失败、半开探测、恢复

**验收标准**:
- 429错误不触发LLM API熔断
- 每个依赖使用独立配置
- 冷却时间正确指数增长
- 单元测试覆盖率 > 90%

## 练习5: 灾难恢复演练 (模块07)

**场景**: 验收你的DR方案，确保数据可恢复。

**任务**:
1. 创建模拟数据（1000个chunks + 向量）
2. 执行全量备份到Parquet/JSONL
3. 执行3次增量备份（每次添加100个新chunks）
4. 模拟灾难：删除主索引
5. 从备份恢复并验证：
   - chunk数量正确
   - 向量维度一致
   - 校验和匹配
   - 可执行基本查询
6. 计算实际RTO并对比目标RTO（1小时）

**验收标准**:
- 恢复后数据完整性 > 99.9%
- 实际RTO < 目标RTO
- 增量备份链完整可恢复
- 备份文件校验和全部通过

## 练习6: 增量更新与回滚 (模块08)

**场景**: 你的增量更新机制在文档批量更新时导致了索引数据不一致。

**任务**:
1. 实现带事务性的增量合并（全部成功或全部回滚）
2. 实现Staging验证：增量数据先在Staging环境合并，验证通过后才写入生产
3. 实现版本冲突检测：并发修改同一文档时使用乐观锁检测
4. 编写回滚测试：模拟合并失败，验证快照恢复是否完整

**验收标准**:
- 事务性合并保证原子性
- Staging验证拦截格式错误的增量数据
- 版本冲突被正确检测和报告
- 回滚后索引状态与合并前完全一致

## 练习7: 蓝绿索引部署 (模块09)

**场景**: 需要在不影响线上服务的前提下完成索引重建。

**任务**:
1. 在Staging环境构建新的HNSW索引（模拟当前索引+100个新向量）
2. 实现指标对比器：对比新旧索引的Recall@10, MRR, NDCG@10, P99延迟
3. 编写决策逻辑：改进>5%则交换，退化>10%则告警，否则保留
4. 实现蓝绿交换函数（原子切换活跃索引引用）
5. 模拟漂移检测：连续记录6次指标后检测是否存在质量退化

**验收标准**:
- 蓝绿交换对查询服务无感知（< 1ms切换时间）
- 指标对比器输出至少8个维度的比较
- 漂移检测正确识别质量退化趋势
- 退化时触发告警（含具体退化指标）

## 练习8: Self-RAG反思循环 (模块10)

**场景**: 标准RAG经常生成与检索文档不一致的回答。

**任务**:
1. 实现完整的Self-RAG反思循环：
   - 检索决策（是否需要检索）
   - 相关性判断（每个文档打分）
   - 支持性评估（回答是否基于文档）
2. 实现自我优化迭代：当判断为partially_supported或contradictory时重新生成
3. 编写3个测试用例：一个需要检索、一个不需要、一个需要多轮优化
4. 对比Self-RAG与标准RAG在相同查询上的回答质量

**验收标准**:
- 反思令牌正确输出和解析
- 最多3轮自我优化
- 每轮优化后质量分数提升
- Self-RAG在事实一致性上优于标准RAG

## 练习9: CRAG回退策略 (模块11)

**场景**: 当知识库不包含查询答案时，系统返回无意义的推测。

**任务**:
1. 实现三级置信度评估器：correct / ambiguous / incorrect
2. 实现知识细化器：对ambiguous结果提取有价值部分
3. 实现Web搜索回退：incorrect时触发
4. 构建测试知识库（故意不包含某些信息）
5. 使用5个测试查询对比CRAG vs 标准RAG的准确性

**验收标准**:
- 置信度评估区分三种级别
- incorrect查询自动触发Web搜索
- ambiguous查询执行知识提取优化
- CRAG准确性优于标准RAG（至少10%提升）

## 练习10: 综合集成 (模块01-13)

**场景**: 你需要设计一个完整的生产级RAG系统架构。

**任务**:
1. 画出系统架构图（文字描述即可），包含以下组件：
   - 数据管道（模块01）
   - 多租户管理（模块02）
   - 四级缓存（模块03）
   - 熔断器+限流（模块05+06）
   - 灾难恢复（模块07）
   - 增量更新（模块08）
   - 索引管理（模块09）
   - 高级检索（模块10-13：根据查询复杂度自适应选择策略）

2. 设计一个请求的完整生命周期（从API网关到返回响应）

3. 制定运维手册大纲（备份、监控、扩容、故障处理）

**验收标准**:
- 架构图覆盖12个以上组件
- 请求生命周期包含至少15个步骤
- 运维手册覆盖4个以上运维场景
- 说明各组件之间的数据流向和依赖关系

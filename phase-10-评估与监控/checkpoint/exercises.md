## 练习 2: RAGAS指标计算

**题目**: 对以下测试样本单独计算所有RAGAS指标:

| 指标 | 含义 | 计算方式 |
|------|------|---------|
| Faithfulness | 回答忠于上下文? | 声明分解+验证 |
| AnswerRelevancy | 回答针对问题? | 逆向生成+相似度 |
| ContextPrecision | 上下文精确度 | 平均精度 |
| ContextRecall | 上下文召回率 | 覆盖比例 |

**测试样本**:
```python
question = "向量数据库有什么优势?"
answer = "向量数据库的检索速度快，能够存储大量数据。机器学习模型可以直接使用向量数据库进行训练。"
contexts = [
    "向量数据库专门用于存储和检索高维向量数据，支持近似最近邻(ANN)搜索。",
    "相比于传统数据库，向量数据库在相似度搜索方面具有数量级的性能优势。",
]
reference = "向量数据库的主要优势包括:高效的向量相似度搜索、支持高维数据存储、以及良好的可扩展性。"
```

**输出要求**:
- 每个指标的得分和计算过程
- 识别回答中的幻觉部分
- 解释为什么语境回溯率表现好/不好

## 练习 3: 检索质量对比

**题目**: 实现两个检索系统的对比评估。

**系统A (BM25)**: 使用BM25进行关键词检索
**系统B (混合)**: 使用BM25+向量混合检索

对以下场景进行对比:
1. 生成50个查询和相应的检索结果
2. 计算HitRate@5, MRR, NDCG@5, Recall@5
3. 使用图表可视化对比结果

**输出要求**:
- 两个系统的指标对比表
- 指标可视化图表
- 统计显著性分析（Welch's t-test）
- 给出"系统B是否优于系统A"的结论

## 练习 4: 构建金标准数据集

**题目**: 构建一个至少包含30条查询的金标准评估数据集。

**要求**:
1. 最少10条人工标注
2. 从至少3篇文档中通过模板生成10条
3. 模拟生产日志挖掘10条

数据必须满足难度分布:
- Easy: 30% (9条) - 直接事实查询

为其中3条easy查询生成对抗变体。

**输出要求**:
- 完整的GoldenDataset对象
- 各维度统计和难度分布
- JSON格式导出
- 数据集验证报告

## 练习 5: A/B测试实验

**题目**: 设计并执行一个完整的A/B测试。

**场景**: 测试两种不同的RAG配置对回答质量的影响。

**配置A (基线)**: 标准RAG (直接检索+生成)
**配置B (实验)**: 增强RAG (查询重写+检索+重排序+生成)

**要求**:
1. 计算所需的样本量（设基线mean=0.75, std=0.08, MDE=0.03, alpha=0.05, power=0.80）
2. 生成模拟数据（A组和B组各有足够样本）
3. 执行Welch's t-test
4. 计算Cohen's d效应量
5. 计算95%置信区间
6. 给出实验结论

**输出要求**:
- 样本量计算过程和结果
- 描述性统计表
- 推断性统计（t, p, d, CI）
- A/B测试报告

## 练习 6: 漂移检测

**题目**: 对你的RAG系统实施数据漂移检测。

使用以下场景:
```python
# 历史基线 (正常时期)
baseline_accuracy = [0.75, 0.77, 0.74, 0.76, 0.78, 0.73, 0.75, 0.76, ...]  # 200个点

# 近期数据 (可能发生漂移)
recent_accuracy = [0.62, 0.58, 0.60, 0.55, 0.57, 0.61, 0.59, 0.54, ...]  # 50个点
```

**要求**:
1. 使用MMD检测数据分布变化
2. 使用KS检验检查漂移
3. 使用z-score进行概念漂移检测
4. 确定系统健康状态（HEALTHY/WARNING/CRITICAL）
5. 如果检测到漂移，给出诊断建议

**输出要求**:
- MMD, KS, z-score的计算结果
- 健康状态判断
- 漂移检测报告

## 练习 8: 持续改进闭环

**题目**: 实现完整的持续改进闭环，至少运行3个优化周期。

**场景**: 改进你的RAG系统，每个周期做一项改进：
1. 周期1: 升级嵌入模型
2. 周期2: 添加重排序
3. 周期3: 优化提示词

**要求**:
1. 设置评估阈值和基线
2. 每个周期执行: 评估→分析→门控→记录
3. 分析是否有回归
4. 生成完整的改进报告

**输出要求**:
- 3个完整周期的记录
- 每个周期的改进分析
- 最终改进报告
- 通过FAIL/WARN/PASS条件验证

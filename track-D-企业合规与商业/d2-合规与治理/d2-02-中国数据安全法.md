# D2-02：中国数据安全法 —— PIPL/DSL/CSL 对 AI 系统的影响

> **核心问题**：在中国境内运营的 RAG 系统，需要遵守哪些数据法规？
> **三大法律**：《个人信息保护法》(PIPL)、《数据安全法》(DSL)、《网络安全法》(CSL)

## 二、PIPL 对 RAG 系统的核心要求

### 2.1 PIPL vs GDPR 关键差异

| 维度 | GDPR | PIPL | 对 RAG 的影响 |
|------|------|------|--------------|
| 被遗忘权 | 第17条 | 第47条 | 类似要求，必须能删除 |
| 数据可携带权 | 第20条 | 第45条 | 必须支持数据导出 |
| 自动化决策 | 第22条 | 第24条 | AI 决策需透明、可解释 |
| 跨境传输 | SCC机制 | 安全评估/认证/SCC | 中国企业更严格的跨境限制 |
| 敏感个人信息 | 特殊类别 | 更广泛定义（含金融/行踪） | 更广的敏感数据范围 |
| 处罚力度 | 最高4%全球营收 | 最高5000万或5%营收 | 均有巨额罚款 |

### 2.2 个人信息处理的合法性基础

```yaml
PIPL 第13条规定了七项合法性基础（与 GDPR 第6条类似但不同）：

RAG 系统通常适用的：
  ✅ 取得个人同意（最常见）
  ✅ 为订立/履行合同所必需
  ✅ 为履行法定职责或法定义务所必需
  ✅ 在合理范围内处理已公开的个人信息

不太适用于 RAG 的：
  ❌ 为应对突发公共卫生事件
  ❌ 为公共利益实施新闻报道
  ❌ 法律规定的其他情形

实践建议：
  1. 用户注册时获取"个人信息收集同意"
  2. 文档上传前确认是否含个人信息
  3. 单独同意用于 AI 训练和分析目的
```

## 三、数据分类分级制度（DSL 第21条）

### 3.1 RAG 系统的数据分类

```
企业内部数据的分类分级：

┌────────────┬──────────────────────┬──────────────────┐
│  级别       │  定义                 │  RAG 系统中的示例 │
├────────────┼──────────────────────┼──────────────────┤
│ 核心数据    │ 危害国家安全/经济命脉 │ 国防/尖端技术文档 │
│ (Core)     │                      │                  │
├────────────┼──────────────────────┼──────────────────┤
│ 重要数据    │ 危害经济运行/社会稳定 │ 关键客户数据     │
│ (Important)│                      │ 财务报告        │
│            │                      │ 未公开的商业战略 │
├────────────┼──────────────────────┼──────────────────┤
│ 一般数据    │ 不涉及上述两类        │ 公开产品文档     │
│ (General)  │                      │ 已发布的技术文章 │
│            │                      │ 公司规章制度     │
└────────────┴──────────────────────┴──────────────────┘

RAG 实践指南：
  - 核心数据 → 禁止上传到云端 RAG 系统
  - 重要数据 → 仅私有化部署，严格访问控制
  - 一般数据 → 可灵活使用
```

### 3.2 实现数据分类的代码示例

```python
class DataClassifier:
    """RAG 系统的数据分类器。"""

    # 敏感关键词列表（需要根据业务扩展）
    CORE_KEYWORDS = ["军事", "国防", "核工业", "尖端武器"]
    IMPORTANT_KEYWORDS = [
        "客户名单", "财务报表", "战略计划",
        "未公开", "机密", "保密", "内部",
    ]

    @classmethod
    def classify(cls, text: str, metadata: dict) -> str:
        """对文档内容进行分级。"""
        text_lower = text.lower()

        # 核心数据检查
        for kw in cls.CORE_KEYWORDS:
            if kw in text:
                return "core"

        # 重要数据检查
        score = 0
        for kw in cls.IMPORTANT_KEYWORDS:
            if kw.lower() in text_lower:
                score += 1

        if score >= 2 or metadata.get("classified", False):
            return "important"

        return "general"

    @classmethod
    def get_storage_policy(cls, level: str) -> dict:
        """根据分类级别返回存储策略。"""
        policies = {
            "core": {
                "upload_allowed": False,
                "message": "核心数据禁止上传",
                "storage": None,
            },
            "important": {
                "upload_allowed": True,
                "message": "重要数据仅限私有化部署",
                "storage": "private_cloud",
                "encryption": "AES-256",
                "access_log": True,
            },
            "general": {
                "upload_allowed": True,
                "message": "一般数据可使用标准存储",
                "storage": "any",
                "encryption": "AES-128",
            },
        }
        return policies[level]
```

## 四、跨境数据传输评估

### 4.1 评估框架

```
跨境数据传输三步走：

步骤1：判断是否涉及跨境
  → 数据存储/处理/LM 调用是否在中国境外？

步骤2：判断数据类型
  → 是否含个人信息？→ PIPL 第38条
  → 是否含重要数据？→ DSL 第25条
  → 是否属于关键信息基础设施？→ CSL 第37条

步骤3：选择合规路径
  → 路径A：通过国家网信部门的安全评估
  → 路径B：获得专业机构的个人信息保护认证
  → 路径C：签订标准合同（SCC for China）
  → 路径D：其他法定条件
```

## 五、等保2.0 与 AI 系统

### 等保等级选择

```
等保2.0 五个等级（AI系统通常涉及前三级）：

第一级（自主保护）：基础防护
  适用: 不涉及用户数据的公开 AI 服务
  要求: 基本安全防护

第二级（指导保护）：较重要系统
  适用: 涉及一般用户数据的 AI 系统
  要求: 身份鉴别、访问控制、安全审计、
        数据完整性、数据保密性

第三级（监督保护）：重要系统 ⭐ 大多数企业AI系统
  适用: 涉及大量个人信息或重要数据
  要求: 除第二级外，还需：
        - 双因素认证
        - 数据库审计
        - 入侵检测/防护
        - 数据加密（传输+存储）
        - 定期安全评估（至少每年一次）
        - 应急预案和演练
```

## 六、自动化决策透明度（PIPL 第24条）

```yaml
AI 系统进行自动化决策时必须满足：

1. 透明度要求：
   - 告知用户正在与 AI 交互（不是人类）
   - 明确说明决策逻辑（可解释性）
   - 提供拒绝自动化决策的选择

2. 公平性要求：
   - 不得基于个人特征进行不合理差别对待
   - 不得设置不合理的交易条件

RAG 系统实践：
  ✅ 在对话开头标注"我是AI助手"
  ✅ 在回答中标注信息来源
  ✅ 提供"转人工"选项
  ✅ 避免基于用户画像的差别定价/服务
  ✅ 保留人工审核通道
```

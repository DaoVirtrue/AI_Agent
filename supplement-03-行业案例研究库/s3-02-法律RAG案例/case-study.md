# S3-02：法律 RAG 案例 —— 多法域判例检索与法条引用系统

---

## 一、业务背景

某大型律师事务所（500+ 律师，服务跨国企业客户）面临法律研究的效率挑战。
律师平均每天花 3-4 小时检索判例、查找法条、核对引用。

**核心需求**：
- 同时检索中国大陆、香港、美国（纽约州/特拉华州）的判例和法条
- 引用精度要求到具体条款（"《民法典》第184条"而非"民法典相关规定"）
- 对幻觉零容忍（法律场景的错误引用可能导致败诉或职业责任）
- 支持复杂的多步法律推理（类似案例 → 适用法条 → 判决倾向）
- 每个客户的案件数据严格隔离

## 三、关键决策

### 决策 1：法条级索引 vs 文档级索引

**选择**：法条级索引（每条法律条文独立为一个检索单元）

**实现**：
- 每条法律条文（如"民法典第184条"）独立为一个 chunk
- 元数据标注：法律名称、条款号、生效日期、修订历史
- 检索时精确匹配到具体条款号
- 优点：引用精度极高。缺点：可能丢失条款间的上下文关系

### 决策 2：判例检索 vs 法条检索分离

**选择**：判例和法条分开索引，并行检索后再融合

**原因**：
- 判例查询："类似本案的情况，法院怎么判的？"
- 法条查询："相关法律条款是什么？"
- 两种查询的语义空间不同，合用索引效果差

### 决策 3：跨法域检索策略

**选择**：每个法域独立索引 + 查询时根据意图路由

**原因**：
- 不同法域的法律体系差异巨大（大陆法系 vs 普通法系）
- 同一条文在不同法域可能有完全不同的含义
- "合同解除"在中国法和美国法下的法律效果完全不同
- 必须由律师明确选择法域，不做自动跨法域混合

## 四、数据管道设计

```
法律数据管道（每日更新）：

1. 法条同步
   → 中国：全国人大/最高法官网爬取 + 北大法宝 API
   → 美国：Westlaw/LexisNexis API（商业许可）
   → 香港：HKe-Legislation 官网
   → 解析：法律名 → 章节 → 条款号 → 条文内容 → 生效日期
   → 版本管理：保留所有历史版本（查询时可指定时间点）

2. 判例同步
   → 中国裁判文书网爬取
   → 美国 PACER/Westlaw API
   → 提取：案件名、法院、日期、争议焦点、判决结果、引用法条
   → 去重 + 去敏感信息（当事人姓名脱敏）

3. 法学评论
   → 法学核心期刊订阅
   → 提取：观点、引用的判例和法条
   → 关联到对应的法条节点（增强法条检索的上下文）

4. 质量控制
   → 新入库法条自动与现有法条做"冲突检测"
   → 新旧条款对比 → 标记变更
   → 建立法条之间的"引用关系"图谱
```

## 五、零幻觉策略

```
法律场景的幻觉防范：

策略1：只检索，不生成（最严格场景）
  对某些高风险查询（"这个案件会赢吗？"），
  系统只返回检索到的原文，不做任何 AI 生成。
  角色：法律检索工具，不是法律顾问。

策略2：逐句引用校验
  生成回答后，逐句检查是否有对应的法条来源。
  无来源的句子自动删除或用"根据一般法律原则"标注。

策略3：检索失败率监控
  实时监控每个法域的检索空结果率。
  如果某个法域的检索失败率突然上升 → 可能索引损坏 → P1 告警。

策略4：引用格式强制
  Prompt 中强制要求引用格式：
  "根据《民法典》第X条：'原文内容...'"
  不使用模糊引用如"相关法律规定"。

策略5：双重校验
  高风险查询（涉及金额 > 100万、刑事案件）：
  两个不同的 LLM 分别生成回答 → 交叉验证 → 不一致的标记人工。
```

## 七、踩坑记录

### 坑1：法条编号体系差异

```
问题：中国法用"第X条"，美国法用"Section X"，香港法用"第X條"。
      统一搜索时，编号体系差异导致精确匹配失败。
教训：不要试图统一编号体系。每个法域用独立的索引和解析器。
      在前端由律师选择法域，系统按法域用对应的编号格式检索。
```

### 坑2：判例的"后续处理"信息滞后

```
问题：一审判决可能被二审改判或被再审推翻。
      如果知识库只有一审判决，律师可能基于过时信息做判断。
教训：每个判例必须标注"后续处理"字段（是否被上诉/改判/推翻）。
      检索时优先展示最终生效判决。
```

### 坑3：律师的隐私关切

```
问题：律师担心自己查询的问题被系统记录后可能暴露客户策略。
      导致部分律师不愿使用系统。
教训：法律 RAG 系统必须实现查询端的隐私保护。
      提供"无痕查询"模式（不留查询日志）。
      所有查询日志加密存储，90天自动清除。
```

## 八、经验教训

1. **法律 RAG 的核心不是"生成"，而是"检索"**。80% 的价值来自精准检索，生成只是辅助。
2. **引用格式必须有行业标准**。法律行业有严格的引用规范，AI 必须遵守。
3. **零幻觉是法律场景的铁律**。宁可回答"未找到相关信息"，也不能编造法条。
4. **跨法域检索的外在复杂度远高于技术复杂度**。真正难的是理解不同法律体系的文化差异。
5. **用户信任需要时间建立**。律师是最怀疑 AI 的群体之一，需要逐案展示准确性来建立信任。

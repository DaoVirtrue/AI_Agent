# S3-01：医疗 RAG 案例 —— 临床指南智能检索系统

---

## 一、业务背景

某三甲医院（3000 床位，年门诊量 500 万次）面临临床决策支持的信息过载问题。
医生每天需要查阅大量临床指南、药品说明书、最新研究文献来做诊疗决策。
传统方式依赖手动检索 PubMed 和纸质指南，效率低下且容易遗漏关键信息。

**核心需求**：
- 快速检索国内外临床指南（NCCN、CSCO、ESC 等）
- 精确检索药品说明书（适应症、禁忌症、相互作用）
- 支持科室定制化（不同科室看到不同的知识库）
- 严格的患者隐私保护（HIPAA + PIPL）
- 准确率要求 99%+（医疗场景的错误代价极高）

## 三、关键决策

### 决策 1：私有化部署 vs 云端 API

**选择**：混合方案 —— 非敏感内容用 API，敏感内容本地 LLM

**原因**：
- 患者隐私数据（脱敏后的查询）不能离开医院内网
- 但普通临床指南检索不涉及隐私
- 最终：敏感数据路由到本地部署的医疗大模型，通用问题走 API

### 决策 2：知识图谱 vs 纯向量检索

**选择**：药品说明书用知识图谱 + 向量混合

**原因**：
- 药品说明书有强结构化关系（药品 → 适应症 → 禁忌症 → 相互作用）
- 向量检索可以找到"相关的药"，但图谱可以找到"有相互作用的药"
- 例如"服用华法林的患者能用阿司匹林吗？"——需要图谱的多个实体间的关系推理

### 决策 3：文档分块粒度

**选择**：指南按章节分块，药品按条目分块

**原因**：
- 临床指南有清晰的章节结构（诊断标准、治疗方案、随访建议）
- 按章节分块确保检索到的是一个完整的"诊断+治疗"单元
- 药品说明书每个条目（适应症/禁忌症/用法用量）是独立的检索单元
- 放弃了统一 chunk_size 的做法，每种文档自定义分块策略

## 四、数据管道设计

```
数据管道（7天更新周期）：

1. 指南采集
   → 爬取 NCCN/CSCO/ESC 等指南网站
   → PDF → OCR → 结构化清洗
   → 人工审核员确认内容完整性
   → 按章节分块 → 嵌入 → 索引

2. 药品说明书同步
   → FDA/NMPA API 每日同步
   → JSON 解析 → 提取字段（适应症/禁忌/用法/相互作用）
   → 图谱更新 → 向量更新
   → 版本号 + 生效日期标记

3. 文献摘要
   → PubMed API 每周拉取最新文献摘要
   → 去重 + 质量过滤（IF > 3, RCT 优先）
   → 嵌入 → 索引
   → 标记证据等级（A/B/C 级）

4. 质量保证
   → 每条管道输出的文档自动运行"事实检查"
   → 对比多个来源的一致性
   → 不一致的标记人工审核
```

## 五、准确率优化

```
从初始 82% 提升到 97% 的优化路径：

优化1：文档分块策略 (82% → 87%)
  问题：固定 512 字符切断了临床指南的"诊断-治疗"逻辑链
  方案：按章节语义分块，确保每个块包含完整的临床逻辑单元
  效果：+5%

优化2：重排序 (87% → 91%)
  问题：向量检索的 Top-K 结果中，正确结果经常排在第 3-5 位
  方案：使用 Cohere Rerank v3 对 Top-20 结果精排
  效果：+4%

优化3：查询改写 (91% → 94%)
  问题：医生使用医学术语缩写，与指南中的全称不匹配
  方案：在检索前用 LLM 将缩写展开（"HTN → hypertension 高血压"）
  效果：+3%

优化4：证据等级加权 (94% → 96%)
  问题：旧指南和新指南权重相同
  方案：根据发布日期和证据等级（A>B>C）调整检索权重
  效果：+2%

优化5：科室个性化 (96% → 97%)
  问题：心内科和肿瘤科对同一问题的关注点不同
  方案：根据医生科室自动添加科室上下文字段，影响嵌入偏向
  效果：+1%

剩余 3% 的差距：
  - 罕见病、超适应症用药等冷门问题
  - 多指南相互矛盾的灰色地带
  - 策略：标记为"建议咨询上级医师"
```

## 七、踩坑记录

### 坑1：PDF 表格解析灾难

```
问题：NCCN 指南中的化疗方案表格在 PDF 转文本时完全错乱。
影响：化疗药物剂量检索完全不可用。
教训：不要用通用 PDF 解析器解析医学表格。必须使用专门的表格提取工具
      （如 Camelot/Tabula）+ 人工验证。对于关键表格数据，
      宁可手动转化为结构化数据再入库。
```

### 坑2：指南版本冲突

```
问题：NCCN 2025 v2 和 v3 对同一疾病的治疗方案有重大调整。
      新旧版本都在知识库中，LLM 会混用两者信息。
教训：建立严格的版本管理机制——每个文档标注生效日期和废止日期。
      检索时必须考虑时效性，默认只检索最新版本。
```

### 坑3：药品相互作用图谱爆炸

```
问题：知识图谱中药品关系随药品数量呈指数增长。
      10万种药品 × 10万种药品 = 百亿级潜在交互边。
教训：不要预计算所有可能的交互。只存储已知的交互对（从药品说明书和文献中提取）。
      查询时实时计算两个药品在1-2跳内是否有交互路径。
```

## 八、经验教训

1. **医疗 RAG 必须有人工审核层**。99% 的 AI 准确率也不够，剩余 1% 可能致命。
2. **文档分块不是一刀切**。不同文档类型需要不同的分块策略。
3. **医学缩写展开是低垂的果实**。简单但效果显著（+3% 准确率）。
4. **时效性比覆盖面更重要**。3年前的指南可能已经过时，宁可回答"未找到最新信息"。
5. **科室个性化**对用户体验影响很大，但技术上复杂度适中。
6. **患者隐私是第一优先级**。从架构设计阶段就考虑 HIPAA/PIPL 合规。

# S3-03：电商 RAG 案例 —— 多模态商品搜索与评价摘要

---

## 一、业务背景

某头部电商平台（年 GMV 5000 亿+，SKU 超过 1 亿）需要升级商品搜索体验。
用户搜索行为日益复杂：从"红色连衣裙"到"适合参加婚礼穿的复古风格长裙，
看起来要显瘦，价格 500-1000"。

**核心需求**：
- 自然语言商品搜索（理解复杂查询意图）
- 多模态搜索（文字 + 图片 + 以图搜图）
- 商品评价智能摘要（从上万条评论中提取关键信息）
- 个性化推荐融合（结合用户画像的 RAG 结果）
- 大促期间 100 倍流量弹性伸缩

## 三、关键决策

### 决策 1：文本嵌入 vs 多模态嵌入

**选择**：文本 + 图片双路嵌入，在融合层汇合

**实现**：
- 商品标题/描述用 BGE-M3 嵌入（中文优化）
- 商品图片用 CLIP 嵌入（OpenAI CLIP-ViT-L/14）
- 用户上传图片用同一个 CLIP 模型嵌入
- 两路检索结果在融合层用加权 RRF 合并

### 决策 2：评价摘要的 RAG 策略

**选择**：预计算摘要 + 实时 RAG 组合

**实现**：
- 离线：每天凌晨对所有商品的评价做批量摘要
  - 提取：好评关键点、差评关键点、常见问题
- 在线：用户查询时，检索最相关的预计算摘要
  - + 实时检索最近的未处理评价
- 效果：延迟低（摘要预计算）+ 信息新（实时补充）

### 决策 3：大促弹性架构

**选择**：预测性扩容 + 降级策略

**实现**：
- 基于历史数据预测大促流量（双11、618）
- 提前 3 天扩容向量库和 LLM 资源
- 降级链：完整RAG → 纯文本检索 → 静态商品列表
- 高峰期自动关闭"评价摘要生成"（最耗 LLM Token）

## 四、数据管道设计

```
商品数据管道：

1. 商品信息同步（实时）
   → 商家后台 API → Kafka → Flink 流处理
   → 结构化提取（标题/描述/属性/价格/图片URL）
   → 文本嵌入 + 图片嵌入 → 写入向量库
   → 同步写入 Elasticsearch（关键词搜索）

2. 评价处理（T+1 离线）
   → 每日凌晨拉取全量新增评价
   → LLM 批量生成评价摘要（好评key/差评key/综合评分）
   → 摘要结果写入商品评价索引
   → 与商品基础信息关联

3. 用户画像更新（准实时）
   → 用户行为日志（浏览/点击/加购/购买）
   → 特征工程（品类偏好/价格带/风格偏好/品牌偏好）
   → 写入用户画像库（影响搜索的个性化加权）

4. 搜索日志回流（T+1）
   → 搜索日志解析（查询词 → 点击商品 → 购买）
   → 构建点击率/转化率模型
   → 反馈到检索权重调整
```

## 七、踩坑记录

### 坑1：图片嵌入模型的中文理解缺陷

```
问题：CLIP 模型对英文商品图片理解好，对中文商品图片（如包装上的中文、
      模特穿着的"国风"元素）理解差。
影响："国风旗袍"以图搜图返回的全是普通连衣裙。
解决：微调了 CLIP 模型（用 10 万对中文商品图文对），
      或改用支持中文的多模态模型（如 Chinese-CLIP）。
```

### 坑2：评价摘要的时效性

```
问题：某商品突然出现大量差评（质量问题曝光），但摘要还是昨天的"好评如潮"。
影响：用户看到好评摘要，购买后发现问题 → 大量退货。
解决：实现评价异常检测——好评率突变（下降 > 20%）触发即时重生成。
      结合实时评价流，对"刚发生的质量事件"快速响应。
```

### 坑3：大促降级伤害体验

```
问题：大促时自动降级关闭了评价摘要，用户看到的搜索结果信息量骤降。
影响：虽然系统没挂，但 CTR 下降了 40%。
解决：不要"一刀切"降级。分级降级：
      L1: 继续完整功能
      L2: 缩短摘要（从 200 字 → 50 字）
      L3: 用预计算的静态摘要
      L4: 纯搜索结果（无 AI 生成）
```

## 八、经验教训

1. **电商搜索的"语义理解"比"关键词匹配"带来质变**。CTR +35% 是最直接的证据。
2. **多模态能力是电商 RAG 的必选项**。用户不只是打字搜索，还上传图片。
3. **评价摘要是低成本的"信任增强器"**。用户看到他人的正面评价，更可能下单。
4. **大促降级必须分级进行**。一刀切降级会严重伤害体验。
5. **个性化与 RAG 的结合是未来方向**。同一查询，不同用户应看到不同结果。

# C3-03：Dify Agent 构建指南

> **Dify Agent**：具备自主决策能力的 AI 助手，可以调用工具、检索知识库、执行代码，并根据中间结果调整策略。
> **核心区别**：普通 Chatbot 只能回答问题，Agent 能自主完成任务。

---

## 一、Agent 架构认知

### 1.1 Dify Agent 工作循环

```
┌─────────────────────────────────────────────────────────────┐
│                     Agent 推理循环 (ReAct)                    │
│                                                              │
│          ┌──────────┐                                       │
│          │  用户输入  │                                       │
│          └─────┬────┘                                       │
│                │                                             │
│                ▼                                             │
│     ┌─────────────────────┐                                 │
│     │  LLM 思考 (Thought) │ ← 分析任务，决定下一步          │
│     └─────────┬───────────┘                                 │
│               │                                              │
│        ┌──────┴──────┐                                      │
│        ▼              ▼                                      │
│   ┌────────┐    ┌──────────┐                                │
│   │ 需要工具│    │ 直接回答 │ ──→ [返回用户]                 │
│   └───┬────┘    └──────────┘                                │
│       │                                                      │
│       ▼                                                      │
│  ┌───────────────────────┐                                  │
│  │ 工具调用 (Action)      │                                  │
│  │ - 知识库检索           │                                  │
│  │ - API 调用             │                                  │
│  │ - 代码执行             │                                  │
│  │ - 网络搜索             │                                  │
│  └───────────┬───────────┘                                  │
│              │                                               │
│              ▼                                               │
│  ┌───────────────────────┐                                  │
│  │ 工具返回 (Observation) │                                  │
│  └───────────┬───────────┘                                  │
│              │                                               │
│              └────→ 回到 LLM 思考（循环）                    │
│                     最多循环 {{max_iterations}} 次             │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 Agent 类型

| Agent 类型 | 推理策略 | 适用场景 |
|-----------|----------|----------|
| **ReAct** | 思考→行动→观察循环 | 通用，工具调用 |
| **Function Calling** | 直接函数调用 | 工具型任务（推荐） |
| **Multi-Agent** | 多 Agent 协作 | 复杂任务分解 |

## 二、Agent 配置实战

### 2.1 基础配置

```yaml
Agent 配置面板：
  名称: "智能客服Agent"
  描述: "处理客户咨询、查询订单、解答产品问题的综合客服Agent"
  
  模型: "GPT-4o / Claude Sonnet 4 / 其他"
  
  系统提示词: |
    你是一个专业的智能客服Agent。
    
    你的能力：
    1. 查询知识库回答产品问题
    2. 通过 API 查询订单信息
    3. 计算价格和折扣
    4. 当无法解决时，整理信息转人工客服
    
    工作原则：
    - 每次只调用一个工具
    - 工具结果不充分时，尝试换个角度检索
    - 回答时标注信息来源
    - 遇到投诉/退款请求，转人工处理
    
    用户信息：
    - 用户ID: {{#user_id#}}
    - 用户等级: {{#user_level#}}
    - 当前时间: {{#current_time#}}
  
  最大迭代次数: 5
  温度: 0.1
  上下文窗口: 16K
```

### 2.2 工具配置

```yaml
可用工具列表：

1. 知识库检索工具
   类型: "知识库"
   知识库: "产品手册库 + FAQ库"
   描述: "查询产品信息、使用方法和常见问题"
   输出: 检索到的文档片段

2. 订单查询 API
   类型: "HTTP 请求"
   URL: "https://api.example.com/orders"
   方法: POST
   描述: "通过用户ID查询最近订单"
   需要参数: user_id

3. 价格计算器
   类型: "代码执行"
   描述: "根据产品价格和用户等级计算最终价格"
   代码: |
     def main(params):
         base_price = params.get("base_price", 0)
         user_level = params.get("user_level", "normal")
         discounts = {"vip": 0.8, "gold": 0.9, "normal": 1.0}
         return {"final_price": base_price * discounts.get(user_level, 1.0)}

4. 工单创建
   类型: "HTTP 请求"
   URL: "https://api.example.com/tickets"
   描述: "当问题无法自动解决时，创建人工客服工单"
```

### 2.3 工具描述的艺术

```
工具描述的质量直接决定 Agent 能否正确使用工具：

【不好的描述】
"查询订单"  ← Agent 不知道什么时候该用

【好的描述】
"查询用户的最近10笔订单，包括订单号、商品名称、金额和状态。
在用户询问'我的订单'、'买了什么'、'订单状态'、'物流'等问题时使用。
需要参数：user_id（从对话上下文自动获取）。"
```

## 三、Agent 构建场景实战

### 场景 1：智能客服 Agent

```yaml
系统提示词核心要点：
  - 先问候用户，引导用户描述问题
  - 判断问题类型：产品咨询 / 订单查询 / 投诉建议
  - 产品咨询 → 知识库检索 → 整理回答
  - 订单查询 → 调用订单 API → 格式化展示
  - 投诉建议 → 安抚用户 → 创建工单 → 转人工
  - 所有回答标注信息来源

工具链:
  知识库检索 → 订单API → 工单创建
```

### 场景 2：数据分析 Agent

```yaml
系统提示词核心要点：
  - 接收用户的数据分析需求
  - 调用数据库查询工具获取数据
  - 用代码执行工具进行统计计算
  - 用 LLM 生成分析报告
  - 如需可视化，生成图表配置

工具链:
  数据库查询 → 代码执行（Python/Pandas） → LLM 总结
```

### 场景 3：文档写作 Agent

```yaml
系统提示词核心要点：
  - 接收写作需求（类型、主题、要点）
  - 检索相关知识库获取素材
  - 生成初稿
  - 自我审查（检查格式、逻辑、引用）
  - 根据用户反馈修改

工具链:
  知识库检索 → LLM 生成 → 自我检查 → 迭代修改
```

## 四、Agent 调试与优化

### 4.1 调试模式

在 Dify Web UI 中，Agent 运行时的每一步都可视化展示：

```
┌─────────────────────────────────────────────────┐
│  Round 1                                         │
│  ├── Thought: 用户想查询订单，需要调用订单API   │
│  ├── Action: 订单查询API                         │
│  │   Input: {"user_id": "U12345"}               │
│  └── Observation: {"orders": [...], "count": 5} │
│                                                   │
│  Round 2                                         │
│  ├── Thought: 已获取5笔订单，整理后回答用户      │
│  └── Answer: "您好，您最近有5笔订单..."          │
│                                                   │
│  Total: 2 rounds, 3.2s, Token: 输入 450 / 输出 180│
└─────────────────────────────────────────────────┘
```

### 4.2 常见问题与优化

| 问题 | 症状 | 解决方案 |
|------|------|----------|
| 工具选择错误 | Agent 不停调用错误的工具 | 优化工具描述，增加使用场景说明 |
| 无限循环 | 反复调用同一工具无进展 | 降低 max_iterations，增加停止条件 |
| 过早放弃 | 工具调用一次失败就放弃 | 系统提示词中鼓励重试，调整错误处理 |
| 幻觉参数 | 调用工具时参数编造 | 工具描述中明确参数格式和取值范围 |
| 信息遗漏 | 回答不全面 | 提示词中增加"检查清单"，确保覆盖所有维度 |

### 4.3 提示词调优模板

```
# Agent 系统提示词模板（生产级）

## 角色定义
你是 [角色名称]，专门负责 [职责范围]。

## 能力边界
你可以做：
1. [能力1]
2. [能力2]
你不能做：
1. [限制1] — 遇到此情况应 [处理方式]

## 工具使用规则
- 每次只调用一个工具
- 调用前确认参数完整
- 工具失败时：[重试策略]
- 不需要工具时直接回答

## 回答规范
- 基于工具返回的事实回答
- 不确定时说明不确定性
- 标注信息来源
- 格式：[具体要求]

## 特殊情况
- [情况A]: [处理方式]
- [情况B]: [处理方式]
```

## 五、Agent 发布与集成

### 5.1 发布方式

```
Dify Agent 支持多种发布方式：
1. Web 应用（Dify 内置 Web UI）
2. 内嵌到网页（iframe / 前端 SDK）
3. REST API（供后端调用）
4. 微信/钉钉/飞书机器人（通过 Webhook）
```

### 5.2 多 Agent 协作

```
┌─────────────────────────────────────────────────────┐
│               Dify 多 Agent 协作模式                  │
│                                                      │
│  模式一：Pipeline（串行）                             │
│  [Agent A: 意图识别] → [Agent B: 任务执行] → 输出     │
│                                                      │
│  模式二：Router（路由）                               │
│              ┌──→ [Agent A: 产品咨询]                │
│  [Router] ──┼──→ [Agent B: 技术支持]                 │
│              └──→ [Agent C: 投诉处理]                │
│                                                      │
│  模式三：Supervisor（监督）                           │
│  [Supervisor Agent]                                  │
│    ├── 委派任务给 Worker Agent A                      │
│    ├── 审查 A 的输出                                  │
│    ├── 如需补充，委派给 Worker Agent B                │
│    └── 整合最终结果                                  │
└─────────────────────────────────────────────────────┘
```

## 六、Dify Agent vs LangChain Agent vs CrewAI

| 维度 | Dify Agent | LangChain Agent | CrewAI |
|------|-----------|----------------|--------|
| 构建方式 | 可视化配置 | Python 代码 | Python 代码 |
| 工具集成 | 内置/HTTP/代码 | 自定义 Tool 类 | 自定义 Tool |
| 多 Agent | 有限支持 | LangGraph | 原生支持 |
| 人机协同 | 通过工具 | 原生 interrupt | 通过工具 |
| 调试体验 | 可视化 | 日志 | 日志 |
| 适用用户 | 全角色 | 开发者 | 开发者 |
| 成本 | 低（配置即完成） | 中（需编码） | 中（需编码） |

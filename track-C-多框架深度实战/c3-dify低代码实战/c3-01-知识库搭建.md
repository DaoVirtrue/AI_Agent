# C3-01：Dify 知识库搭建指南

> **Dify 是什么**：开源 LLM 应用开发平台，提供可视化的 Prompt 编排、RAG 管道、Agent 构建、工作流设计。
> **核心理念**：让非技术人员也能构建 AI 应用，技术人员可以更快地迭代。

## 二、知识库创建（Web UI 操作）

### 步骤 1：创建知识库

1. 登录 Dify → 导航到「知识库」→ 点击「创建知识库」
2. 配置基本信息：

| 配置项 | 说明 | 建议 |
|--------|------|------|
| 名称 | 知识库名称 | 见名知义，如「产品手册库v2」 |
| 描述 | 用途说明 | 方便团队成员理解 |
| 权限 | 团队可见/仅自己 | 多成员协作时选团队可见 |
| 索引方式 | 高质量/经济 | 生产环境选高质量 |
| 嵌入模型 | 文本向量化的模型 | 中文推荐 BGE-M3 |
| 检索设置 | 混合检索/向量检索/全文检索 | 默认混合检索 |

### 步骤 2：上传文档

**支持格式**：
- 文本：TXT, Markdown, PDF, DOCX, HTML
- 表格：CSV, XLSX
- 代码：Python, JavaScript, Java, Go 等

**三种上传方式**：
1. **拖拽上传**：直接从本地拖拽文件到页面
2. **网页抓取**：输入 URL，自动抓取网页内容（支持递归爬取）
3. **API 导入**：通过 API 程序化导入（见 C3-04）

**分段设置**：

| 参数 | 说明 | 中文场景推荐值 |
|------|------|----------------|
| 分段最大长度 | 每个 chunk 的最大字符数 | 500-1000 |
| 分段重叠长度 | 相邻 chunk 的重叠字符数 | 50-100 |
| 分段标识符 | 按什么标记分段 | 自动（或选择 `\n\n`） |
| 预处理规则 | 清除多余空格/URL/邮箱 | 全部开启 |

**高级分段**（仅高质量模式）：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 自动分段 | LLM 自动判断语义边界 | 通用（推荐） |
| 自定义分段 | 手动设置规则 | 已知文档结构 |
| Q&A 分段 | 按问答对组织 | FAQ/知识问答 |

### 步骤 3：等待索引

- 文档上传后，Dify 在后台进行：清洗 → 分段 → 嵌入 → 索引
- 在知识库详情页可看到「正在处理中...」状态
- 处理完成后显示「已完成」

### 步骤 4：检索测试

在知识库页面内置的「检索测试」中可以：
- 输入查询文本
- 查看检索到的分段和相关性分数
- 调整检索参数实时观察效果
- 引用来源自动标注

## 三、检索配置优化

### 3.1 检索模式选择

| 模式 | 原理 | 适用场景 | 延迟 |
|------|------|----------|------|
| **向量检索** | 纯语义相似度 | 概念性问题 | 中 |
| **全文检索** | BM25 关键词匹配 | 精确关键词/编号 | 低 |
| **混合检索** | 向量+全文 RRF 融合 | **通用推荐** | 中 |
| **N-choose-1** | LLM 从 N 个候选中选最佳 | 需要对精确度极致要求 | 高 |

### 3.2 Top K 设置

| Top K | 优点 | 缺点 | 建议 |
|-------|------|------|------|
| 1-2 | 结果最精准 | 可能遗漏相关信息 | 简单事实问答 |
| 3-5 | 精准度与覆盖度平衡 | **推荐默认值** | 通用 RAG |
| 6-10 | 覆盖面广 | 噪声增多，LLM 处理成本增加 | 复杂问题/多文档场景 |
| >10 | 极少使用 | 严重噪声，延迟高 | 特殊场景（如摘要全库） |

### 3.3 分数阈值

```yaml
推荐配置 (基于混合检索):
  top_k: 5
  score_threshold: 0.5    # 低于此分数的结果丢弃
  rerank_enable: true      # 启用重排序
  rerank_top_k: 3          # 重排序后保留的数量
  rerank_model: "BAAI/bge-reranker-v2-m3"
```

## 四、知识库管理最佳实践

### 4.1 文档组织策略

```
推荐的知识库分库策略：

方案A：按业务领域分库（推荐）
├── 产品知识库
│   ├── 产品手册
│   ├── 功能说明
│   └── 版本发布记录
├── 技术知识库
│   ├── 架构文档
│   ├── API 文档
│   └── 运维手册
└── 规章制度库
    ├── 公司制度
    └── 合规政策

方案B：按部门分库
├── 研发部知识库
├── 销售部知识库
└── 客服部知识库

方案C：按安全等级分库
├── 公开知识库
├── 内部知识库
└── 机密知识库（需额外权限）
```

### 4.2 文档质量管理

```yaml
上传前检查清单：
  - [ ] 文档格式规范（标题、段落、编号清晰）
  - [ ] 去除水印、页眉页脚等干扰信息
  - [ ] 图片中的文字已 OCR 提取
  - [ ] 表格格式完整（无合并单元格导致的结构错乱）
  - [ ] 无敏感信息（或已脱敏处理）
  - [ ] 文件名清晰表达内容
  - [ ] 格式统一（避免混用中英文标点、全半角字符）
```

### 4.3 维护流程

```
文档生命周期管理：

1. 新增文档 → 上传 → 自动索引 → 检索测试 → 发布
2. 修改文档 → 删除旧版 → 上传新版 → 自动索引 → 验证
3. 删除文档 → 从知识库中移除 → 向量自动清理
4. 定期审查 → 检查检索效果 → 更新分段策略 → 清理冗余文档
```

### 4.4 效果评估

```python
# 人工评估知识库效果的标准
评估维度 = {
    "召回率 (Recall)": "相关文档有多少被检索到",
    "精准率 (Precision)": "检索到的文档中有多少是相关的",
    "首条命中率 (Hit@1)": "第一个检索结果就是正确答案的比例",
    "MRR (平均倒数排名)": "第一个相关结果的平均排名倒数",
}

# 建议定期（每周/每月）用一组标准问题评估
测试问题集 = [
    "公司年假政策是什么？",
    "如何申请报销？",
    "产品的退款流程？",
    ...
]
```

## 六、常见问题与解决方案

**Q1: 检索结果不相关怎么办？**
A: 依次检查：分段大小是否合理（尝试缩小到 300-500）→ 切换检索模式（混合→N-choose-1）→ 检查文档质量（是否有大量噪声）

**Q2: 中英文混合文档检索效果差？**
A: 使用多语言嵌入模型（BGE-M3），或分两个知识库分别用不同嵌入模型

**Q3: 知识库更新后旧答案仍出现？**
A: 确认文档删除后向量已清理，可手动触发全量重建索引

**Q4: PDF 表格解析错误？**
A: 将 PDF 中的表格单独导出为 CSV，作为独立文档上传
